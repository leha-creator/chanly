# Private channel approval also requires database policy alignment

**Date:** 2026-11-03
**Files:** migrations/00016_channel_visibility_policy.sql, internal/channel/app/catalog_test.go
**Severity:** medium

## Problem

Approving a private channel on dev returned HTTP 500 with SQLSTATE 23514 for channel_active_requirements.

## Root Cause

The dev visibility exception was covered by domain tests and linking tests, but approval was not exercised through PostgreSQL. The database independently required is_public for active channels.

## Solution

Migration 00016 moves environment-dependent visibility enforcement to channel/domain, like the RKN threshold. It retains organization, category and write/delete database requirements and the price trigger. The existing approval logs record missing requirements and successful decisions. Down restores the original check and fails transactionally if private active channels remain.

## Prevention

Test the entire persisted transition for environment-dependent eligibility rules. The regression now verifies strict-policy rejection and dev-policy approval against the same private channel through Service.Approve and PostgreSQL, preserving is_public=false. Search migrations for duplicate eligibility constraints when changing a domain policy.
