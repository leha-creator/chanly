# MAX rights events can precede channel discovery

**Date:** 2026-11-03 19:40 UTC
**Files:** internal/channel/app/events.go, internal/channel/jobs/jobs.go, internal/channel/app/events_test.go
**Severity:** medium

## Problem

A valid channel link code remained pending because the channel did not exist locally.

## Root Cause

Discovery assumed MAX would always send bot_added. Live MAX instead sent bot_admin_permissions_changed with is_channel=true and no user. The handler ignored unknown chats.

## Solution

Pass channel type and optional actor through routing. Create an unclaimed channel transactionally on an unknown channel rights event and enqueue the existing authoritative rights refresh. Keep known channel handling unchanged so stale rights events cannot revive disconnected channels or replace ownership. A live link code still assigns the organization. Add a structured [FIX] discovery log without post content or codes.

## Prevention

Test real payload shapes without optional actors and without assumed predecessor events. Cover early-code retry, duplicates, owner preservation, disconnected channels and nonchannel events. Never route all rights changes through BotAdded, which has different lifecycle semantics.
