# Release gates must distinguish safe CHECK widening and concurrent bootstrap

**Date:** 2026-11-12 01:22 Europe/Astrakhan
**Files:** deploy/scripts/check-migrations.sh, deploy/scripts/reviewed-migration-expansions.txt, deploy/tests/migration-guards.sh, .github/workflows/ops.yml, deploy/app/README.md, internal/account/postgres/platform.go, internal/account/postgres/queries/organizations.sql, internal/account/postgres/sqlc/organizations.sql.go, internal/account/domain/ports.go, internal/account/app/platform_concurrency_test.go
**Severity:** high

## Problem

Delivery of 0cd8ea6 stopped because the migration guard rejected 00105's DROP
CONSTRAINT despite its transactional CHECK widening. The preceding release
rehearsal also failed when API and worker created the platform simultaneously.

## Root Cause

The migration gate classified every constraint replacement as destructive.
Changing an already committed migration would violate immutability. Platform
bootstrap separately read a missing row then inserted; concurrent startup saw
the same absence and misclassified the winner's unique INN as an ordinary
organization conflict.

## Solution

Keep 00105 unchanged. Permit only its exact committed path and SHA256 through a
reviewed expansion manifest; retain all existing-file and destructive checks.
Add isolated Git fixture regression tests and an explicit reviewed-expansion log.
Serialize platform bootstrap with a transaction-scoped advisory lock before a
separate READ COMMITTED SELECT, with configurable [FIX] debug logging.

## Prevention

Test exact digest/path, tampering, immutable edits/deletes/renames, unknown
destructive SQL, normal expansion and existing contract markers. Verify the
guard against 3740042, since the next push itself adds no migration. Exercise
startup with the first INSERT held uncommitted, observe the second backend
waiting, then commit/rollback; assert one platform and creation audit. Preserve
real conflicting configuration and ordinary-organization INN errors. A lock and
SELECT in the same statement would retain an old snapshot and is insufficient.
