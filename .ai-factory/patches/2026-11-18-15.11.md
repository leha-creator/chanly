# CDN allowlist must cover provider domain families

**Date:** 2026-11-18 15:11 Europe/Astrakhan
**Files:** internal/platform/outbound/media.go, media_test.go; internal/bootstrap/config_support.go, config_support_test.go; internal/support/app/attachments.go, attachments_test.go; .env.example; deploy/app/env/*/app.env.example; docs/support.md
**Severity:** medium

## Problem

The first real incoming support image displayed an attachment failure while its
text message arrived. The media job had completed with a failed attachment and
no private storage object.

## Root Cause

The CDN list was inferred from upload examples and contained iu.oneme.ru but
excluded the actual incoming image host i.oneme.ru. Exact-host validation also
required a configuration change for every new CDN subdomain. Source failures
were reduced to a generic status, obscuring the allowlist rejection.

## Solution

Support explicit *.domain rules while preserving exact-host semantics. Defaults
and environment templates include oneme.ru, *.oneme.ru, okcdn.ru, *.okcdn.ru.
Match full DNS-label boundaries, reject lookalikes and malformed hosts, retain
HTTPS-only URLs, DNS pinning, public-IP checks, no redirects and no bot token
forwarding. Log bounded source reason codes and HTTP status without private
URLs, paths, signatures, filenames, provider bodies or tokens. Update only the
dev support setting and requeue the one failed inbound image through its media
job; outgoing message delivery rules remain unchanged.

## Prevention

Regression tests cover current image/file hosts, future nested subdomains,
exact-host compatibility, suffix lookalikes, credentials, IP literals, ports,
top-level wildcard rejection and private-address checks. A media preparation
test stores a synthetic PNG from trusted subdomains, rejects an untrusted
lookalike without an HTTP request, and asserts that private source values never
appear in logs. Validate actual inbound and upload origins separately.

Targeted Go regressions and go vet passed. Dev release
dev-support-cdn-20261118 is healthy. The reported real image was recovered into
private storage (ready, image/webp, 58616 bytes); its provider URL/token were
cleared. Primary bot configuration and webhook subscriptions matched their
pre-release baseline after the rollout.
