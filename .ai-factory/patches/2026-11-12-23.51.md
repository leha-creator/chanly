# Ready RocketWork executors were blocked by their status information source

**Date:** 2026-11-12 23:51 Europe/Astrakhan
**Files:** internal/integration/rocketwork/executors.go, internal/integration/rocketwork/executors_test.go, docs/05-integrations.md
**Severity:** medium

## Problem

A connected self-employed executor remained pending even though RocketWork
returned payment_readiness=all_is_well and selfemployed_status=validated.
The only self-employment information source in the response was free_smz.

## Root Cause

The adapter imposed an undocumented requirement for exactly one validated
rocketwork entry in the optional selfemployed_profiles list. It treated the
information source as an additional permission gate despite the ready summary.
An existing test encoded the same incorrect assumption for empty profiles.

## Solution

Use the documented top-level readiness and self-employment fields. Keep identity,
employment-kind, missing-permission, missing-requisite and unknown-state checks.
Lookup and paginated search accept ready executors independently of their profile
information source. Add configurable [FIX] debug logs containing status fields
without credentials or personal data, and document the admission rule.

## Prevention

Cover ready free_smz and alfa sources, empty and omitted profiles through lookup
and search. Keep negative cases for missing rights, requisites, registration,
unverified self-employment, unknown/null readiness and employment mismatch.
Preserve identity-conflict and ambiguous-search rejection tests. Treat optional
descriptive API fields separately from documented readiness decisions.

Validation: adapter/fake tests, all payout packages and bootstrap/bridge tests
passed with CI=true and isolated PostgreSQL; adapter go vet and diff checks passed.
