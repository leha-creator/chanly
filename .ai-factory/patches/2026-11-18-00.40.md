# Preserve verified Telegram egress during application releases

**Date:** 2026-11-18 00:40
**Files:** deploy/telegram/install.py, deploy/tests/telegram-proxy.py, deploy/app/README.md
**Severity:** critical

## Problem

The approved invoice release failed before starting the application. Production
PostgreSQL also stopped after the shared disk filled up. Removing unused old
Docker images and builder cache restored database and application health.
The release retry then failed with URLError while replacing a healthy Telegram
proxy with the first unavailable profile from the same subscription.

## Root Cause

Uncompressed archived WAL consumed most of the 40 GB shared disk. The installer
reported only OSError, hiding ENOSPC, and truncated private files before writes
completed. Every application deployment also replaced the working proxy without
first checking whether it already satisfied the required connectivity policy.

## Solution

Verify the existing configuration, subscription identity, runtime UID/GID and
both positive and negative network probes before retaining the running proxy.
An unhealthy proxy or changed subscription still follows installation and rollback.
Write private files through private temporary siblings, fsync and atomic replace;
publish candidate configuration only after the supporting files are written.
Log numeric errno and its symbolic name without exception messages or secrets.

Eight local regression tests cover the retained healthy proxy, subscription
changes, failed probes, invalid routing, private replacement, ENOSPC preservation
and redacted errors, alongside the existing subscription security tests.

## Prevention

- Inspect both Docker cache and object-store backup usage during disk incidents.
- Preserve database files, archived WAL and configured backup retention.
- Exercise failure before atomic replacement and verify original bytes survive.
- Treat a verified existing shared dependency as sufficient for an app release.
- Never include subscription URLs, exception text or subprocess stderr in errors.
