# История поддержки теряла высоту из-за оболочки страницы

**Дата:** 2026-11-18, Europe/Astrakhan
**Серьёзность:** medium
**Файлы:** frontend CabinetLayout, AdminCabinetLayout, adm-support, send-support-message, record-support-voice, SupportMedia, SupportAudioPlayer; docs/support.md

## Проблема и причина

Даже компактная шапка диалога оставляла мало места сообщениям. Общая оболочка
админки резервировала отдельный верхний ряд, отступы контента и большой заголовок
страницы. Каждое сообщение повторяло автора и дату отдельной строкой; нативный
аудиоплеер и форма ответа занимали лишнюю высоту. Изменение только внутренних
панелей не устраняло суммарные потери пространства.

## Исправление

Добавлен явный режим contentLayout=messenger только для маршрута /adm/support.
Он использует доступную высоту окна без вычитания приблизительных констант.
Заголовок очереди находится слева, компактная шапка диалога и авторастущее поле
ответа оставляют основное пространство истории. Колокольчик уведомлений и
мобильная навигация сохранены, дублирующая плавающая кнопка поддержки скрыта.
Другие разделы продолжают использовать обычную оболочку страницы.

Дата выводится разделителем, время и результат отправки — внутри сообщения.
Медиапревью ограничены по высоте, оригиналы доступны по нажатию/скачиванию.
Аудио имеет компактные доступные кнопки, перемотку, длительность и скачивание;
нативный media element продолжает читать защищённый endpoint. Панель записи
и вложения раскрываются только при использовании.

По дополнительному запросу пользователя начальный фильтр изменён на все
обращения, включая закрытые. Явный выбор другого фильтра сохраняется в URL.

## Предотвращение

Проверяется реальная геометрия: история не ниже 700 px в окне 1920×900,
шапка не выше 72 px, пустая форма не выше 80 px, страница без внешней прокрутки.
Проверены ширины 360/390/768/1440 и короткое окно 390×640, воспроизведение,
перемотка, запись, вложения, черновики, статусы и защита от повтора unknown.
Регрессия оболочки проверяет уведомления и восстановление обычного режима
после перехода в другой раздел. Windows WebKit проверяет доступный fallback;
его ограничения не считаются проверкой нативных кодеков Safari на устройстве.

Проверки: yarn verify — 236 файлов, 1511 тестов, типы, линтеры, формат,
сборка и bundle budget; 10 сценариев Chromium/WebKit, включая начальный фильтр.
Dev frontend: e3dec18c20108f8246c9edb97acb21d8cb0a415a. Проверены версия,
health, доступ к API и webhook. Настройки и подписка основного бота совпадают
с исходным снимком. Backend в этом выпуске не менялся.
