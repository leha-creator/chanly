## Как выбрать план

Указывать файл явно, поскольку планы используют существующую ветку:

```text
$aif-implement @.ai-factory/plans/feature-checks-max.md
$aif-implement @.ai-factory/plans/feature-checks-ord.md
$aif-implement @.ai-factory/plans/feature-checks-rocketwork.md
$aif-implement @.ai-factory/plans/feature-checks-tbank.md
```

Каждая строка запускает работу только по выбранному сервису. Коммиты и критерии завершения описаны в соответствующем плане; ожидание ответа провайдера не даёт основания отмечать проверку выполненной.

## Связи между планами

- Подтверждение Q-02 закреплено за задачей 2 плана ОРД. Рокет Ворк использует это решение для зависимых операций; завершения всего плана ОРД ждать не нужно. Т-Банк использует существующую оплату по счёту и обращается к Q-02 только при необходимости изменения договорной схемы.
- Общий живой прогон MAX + ОРД закреплён за задачей 5 плана ОРД и использует результаты задачи 3 плана MAX. Эта зависимость не препятствует подготовке или отдельным проверкам любого сервиса.
- Автоматическое пополнение через Т-Банк выполняется независимо от доступа к Рокет Ворк. Выплаты блогерам проверяются в плане Рокет Ворк.
- Матрица доказательств остаётся общей: `docs/launch/integration-checks.md`. Каждый план обновляет только относящиеся к нему записи. Общая команда `maxim integration-check`, bootstrap, env-шаблоны и документация дорабатываются по месту с учётом остальных сервисов.
- При запуске каждого плана актуализировать его сведения о доступах; текущие статусы в этой карте — снимок на дату разделения.

## Критерии завершения общего этапа

- Выполнены критерии всех четырёх сервисных планов; вопросы имеют доказанный ответ либо явно согласованное ограничение, реализованное и проверенное в коде. Q-09 повторно не открывается.
- Q-02 подтверждён ответственными. Есть фактические живые результаты MAX с требуемым сроком удаления, sandbox ОРД, тестовые сценарии Рокет Ворк и автоматического пополнения через Т-Банк; локальные тесты их не заменяют.
- Общий прогон MAX + ОРД завершён; адресные регрессии и обязательные проверки репозитория проходят, безопасность денежных повторов подтверждена.
- Документация соответствует результатам, тестовые публикации убраны в пределах API, оставшиеся ресурсы/задания учтены. Production-доступы, включение боевой синхронизации и запуск пилота остаются отдельным этапом.
- Завершение отдельного плана не закрывает milestone. Общий статус обновляется владельцем артефакта через `$aif-roadmap` только после всех критериев.
