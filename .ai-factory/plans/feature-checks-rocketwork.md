## Объём и критерии готовности

Рабочий объём — ВСЕ операции, необходимые для полного сценария выплат платформы: подключение исполнителя, договор/сделка, акт, выплата после приёмки размещения, чек, события и опрос, отказ/отмена, безопасное восстановление, депозит и поддерживаемый вывод собственных средств. Вакансии, отклики, анонимные выплаты, кошелёк и эквайринг не добавляются в продукт без расширения задачи.

«Соответствует OpenAPI» означает: каждый используемый маршрут, метод, заголовок, тело и ответ имеет проверку по зафиксированному документу; нет недокументированных полей и подмены бизнес-смысла. Это не обещание реализации каждого endpoint публичного API.

Два независимых результата:

1. **Локальная реализация завершена:** задачи 1–17 выполнены, сценарии реализованы и проверены без провайдера. Отсутствие sandbox не оставляет общий ErrDisabled вместо доступной по OpenAPI функциональности.
2. **Внешняя совместимость подтверждена:** задача 18 имеет фактические результаты; доступы, параметры договоров и денежный процесс проверены. До этого production-автоматизация не включается.

Неизвестные тарифы/договоры/налоговые параметры блокируют конкретный реальный запуск с понятной причиной, а не разработку адаптера и локальных сценариев. Неподдержанные документом возможности получают явный результат unsupported и процедуру ручного разрешения.

## Исходное состояние и важные уточнения

На 2026-11-09 уже есть:
- Чтение /api/account, /api/tasks/{id}, поиск /api/tasks по external_ids[]; точные денежные суммы, консервативное сопоставление статусов, Bearer-события сделок.
- Запрет старых выдуманных запросов, production-live, небезопасных URL и redirect. Полный go test ./... и go vet ./... проходили; локальный прогон был без -race (CGO_ENABLED=0).
- Внутренние payout/app/jobs/postgres, bridge, ledger, fake и e2e; частично обновлённая документация. Эти части требуют проверки и расширения, а не создания параллельного модуля.
- Незакоммиченные изменения предыдущего запуска и пользовательская OpenAPI. Сохранить их, не сбрасывать и не прятать автоматически.

Уточнения по документу, которые заменяют прежние обобщённые блокировки:
- GET /api/executors/{id} документирует телефон/ИНН/email. Числовой executor.id — отдельное значение, его нельзя молча подставлять в этот маршрут.
- POST /api/executors имеет разные варианты. Для ИП описаны необходимые ФИО, телефон, ИНН и employment_kind без обязательных паспортных полей. Для самозанятых используется приглашение/регистрация у RW, если полная API-регистрация потребовала бы паспорт.
- POST /api/executors/invite отправляет SMS, а не гарантирует onboarding_url. rebind запрашивает права ФНС; не заменяет регистрацию и не должен автоматически спамить при каждом опросе.
- POST /api/tasks подписывает договор Заказчиком уже при создании. Выплата — отдельная стадия. autosignable/autocomplete/autopayable и tax_retention должны иметь явную политику.
- /api/tasks/{task_id}/refund описан как возврат покупателю при эквайринге, НЕ возврат выплаты блогеру. Аннулирование НПД-чека и reversal выплаты не выводить из этого endpoint.
- type=Withdrawal документирован для вывода собственных средств. Это отдельная административная операция, не возврат долга блогера и не обычный payout.
- external_id документирован для идемпотентности создания сделки; уникальность, область/срок гарантии и поиск после задержки не проверены живым API. Для PATCH действий аналогичная гарантия не предполагается.
- Подписки используют Authorization; HMAC старого fake не является контрактом RW. События не являются командой принять деньги или окончательный статус без сверки.
- В схеме встречаются дефекты/неоднозначности: type=https в securitySchemes, required=true внутри свойства, nullable/allOf, примеры статусов, детали sign_act/cancel, форма postback data. Отметить точные JSON Pointer и предел каждой проверки.

## Карта операций

| Возможность | OpenAPI | Решение |
|---|---|---|
| Доступ/остаток | GET /api/ping, /api/account | Реализовать и проверить; balance — денежное значение, не доказательство доступности выплаты |
| Поиск исполнителя | GET /api/executors, /api/executors/{id} | Пагинация, точная проверка принадлежности/идентичности, не доверять первому fuzzy-совпадению |
| Регистрация/обновление ИП | POST /api/executors | Ветка entrepreneur; изменение только разрешённых полей и без обхода чужой идентичности |
| Самозанятый/права ФНС | POST /api/executors/invite, /api/executors/rebind | Явные действия, сохранение результата, лимиты повторов; паспортов нет |
| Сделки | GET/POST /api/tasks, GET /api/tasks/{id} | OneTime; external_id и immutable снимок условий, поиск перед повтором |
| Завершение/акт/оплата | PATCH /api/tasks/{task_id}/complete, /sign_act, /pay | Раздельные операции с контрольными точками; GET для сверки результата |
| Отмена | PATCH /api/tasks/{task_id}/cancel | Только документированные допустимые состояния; не возврат уже выплаченных денег |
| События | GET/POST /api/postback_subscriptions, DELETE /api/postback_subscriptions/{id}, GET /api/postbacks | Явное управление своей подпиской, восстановление пропусков, проверка версий и авторизации |
| Вывод остатка | POST /api/tasks с type=Withdrawal и необходимые документированные стадии | Отдельная админ-операция с проверкой принадлежности реквизитов; доступ может зависеть от аккаунта |
| Возврат выплаты/чека | Отдельного подтверждённого endpoint не найдено | Явное ограничение + ручная сверка, без фиктивного автоматического возврата |
| Эквайринговый refund, vacancies/applications, прочие типы сделок | Присутствуют в OpenAPI | Вне payout-сценария; записать в матрицу покрытия, не заявлять их реализованными |
