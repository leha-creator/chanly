## Настройки

- Testing: yes — автоматические регрессии по подтверждённым контрактам и отдельные живые проверки.
- Logging: verbose — DEBUG для шагов и диагностики, INFO для результатов, WARN для неподтверждённых возможностей, ERROR для сбоев. Использовать `log/slog`, JSON и штатный `LOG_LEVEL`; исключить токены, секреты Webhook, персональные данные и полные тела запросов.
- Docs: yes — обязательное обновление документации через `$aif-docs`.
- Язык: русский, имена API, параметры и пути сохраняются.

## Цель и границы

Подтвердить контракт Рокет Ворк, исправить клиент по фактической документации и проверить выплаты блогерам в тестовом контуре. Т-Банк используется для входящих пополнений рекламодателей в собственном плане.

Milestone: «Проверки и доступы». Вопросы этого плана: Q-10–Q-12. Q-09 закрыт и повторно не открывается.
Источники: `docs/open-questions.md`, `docs/05-integrations.md`, `docs/06-finance-legal.md`, `docs/launch/integration-checks.md`, `.ai-factory/ARCHITECTURE.md`; исторический контекст — Active Summary `.ai-factory/RESEARCH.md` от 2026-10-12. Исторические допущения не считать свежим подтверждением внешнего контракта.

Общие адаптеры `outbound`, ограничения частоты и маскирование сохраняются. Существующую `maxim integration-check` расширять только сценариями этого сервиса, учитывая изменения остальных планов. Общие файлы сборки, CLI и матрицы проверок редактировать по месту, не создавать параллельную диагностическую команду.
Preflight подтверждает конфигурацию; live-результат требует настоящего адаптера и ответа провайдера. Fake, disabled и `APP_ENV=test` не подтверждают live-доступ. Проверочный стенд использует выделенные БД, хранилище и ресурсы; текущая диагностическая команда требует `APP_ENV=development`, production для неё запрещён. Изменяющие операции требуют явного режима и сохранения состояния запуска; неизвестный исход не разрешает слепой повтор.
Доступы и ответы внешних сторон зависят от владельца/провайдера. Их отсутствие не блокирует локальную подготовку, но соответствующие проверки остаются открытыми. Секреты не помещать в план, fixtures или журнал. Реальные выплаты, запуск пилота, публикации в рабочих каналах и автоматическая отправка запросов провайдерам в план не входят. Подготовка вопросов входит; отправка обращений требует отдельного поручения.

Клиент Рокет Ворк содержит предполагаемые URL, тела, авторизацию, идемпотентность и подпись; прежние тесты не доказывают совместимость. Production остаётся `disabled` до подтверждения контракта. Параметры общего решения Q-02 берутся из задачи 2 [плана ОРД](feature-checks-ord.md); весь план ОРД для этого завершать не требуется.
