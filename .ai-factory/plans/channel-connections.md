# Подключение канала MAX без публикации в ленте

Дата: 2026-11-11. Работа в текущем checkout, без коммита и развёртывания.

## Настройки

- Testing: yes — адаптер MAX, сценарии с PostgreSQL, HTTP и mockapi.
- Logging: structured DEBUG/INFO; токен и ссылка запуска не попадают в журнал.
- Docs: обновить существующую инструкцию и контракт API.

## Решения

Кабинет получает одноразовую ссылку на личный диалог с ботом. `bot_started`
связывает сессию подключения с пользователем MAX. Worker проверяет обнаруженные
каналы через `GET /chats/{chatId}/members?user_ids=...`; допускается владелец
либо администратор с правом `write`. Права бота — `write` и `delete`.
Кандидаты видны только инициатору сессии в его организации. Выбор канала
запускает повторную проверку прав в worker и атомарную привязку.
Событие добавления бота используется для обнаружения, но не для авторизации.
Сессии и кандидаты имеют срок действия, проверки постраничные, внешние вызовы
вне транзакций. Старый API кодов остаётся deprecated для совместимости старых
клиентов; новый основной сценарий не создаёт сообщений в канале.
Продуктового frontend в репозитории нет: реализуются API и mockapi.

## Задачи

- [x] 1. Адаптер MAX и модель хранения: `integration/max`, `channel/domain`, миграция,
  `channel/postgres/queries`, sqlc. Одноразовый случайный токен не менее 128 бит,
  хеш в БД, организация и инициатор; проверка прав человека по ID.
  DEBUG: вызовы репозитория и API без токена.
- [x] 2. Сценарии `channel/app`, `channel/jobs`, `bootstrap`: выдача ссылки,
  `bot_started`, ограниченный постраничный поиск, обновление и подтверждение,
  свежая проверка и блокировка канала, истечение и повторы. INFO: смена состояния;
  DEBUG: пропуски и число кандидатов. Зависит от 1.
- [x] 3. Контракт и обработчики API, mockapi и существующая документация:
  создание/чтение/обновление/подтверждение сессии, понятные статусы и причины,
  инструкции без публикации. Генерация OpenAPI; DEBUG: операции без секретов.
  Зависит от 2.
- [x] 4. Проверки адаптера, сценариев и HTTP: одноразовость, чужие сессии,
  недостаточные и отозванные права, конкурирующие организации, повтор запросов,
  отсутствие публикаций/удалений в новом сценарии. Сборка и подходящие тесты;
  честно зафиксировать недоступные проверки. Зависит от 3.

двух worker и постраничный поиск 24 каналов; `go vet ./...`;
в `mockapi` — `go test ./... -count=1`, включая все операции OpenAPI.
