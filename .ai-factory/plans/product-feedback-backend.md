## Настройки

- Testing: yes — тесты критичных сценариев; существующие проверки расширять только при пробеле в покрытии.
- Logging: standard — `slog`, INFO для успешных изменений, WARN для ожидаемых отказов, ERROR для сбоев; DEBUG включается конфигурацией. Не журналировать реквизиты, документы, текст постов/требований, токены и подписанные URL.
- Docs: yes — обязательное обновление OpenAPI и затронутых документов через `$aif-docs` при реализации.
- Язык: русский, по языку запроса и подтверждённым настройкам пользователя; корневой `.ai-factory/config.yaml` и `skill-context/aif-plan/SKILL.md` отсутствуют.
- Граница работы: Go API/worker, PostgreSQL, контракты и backend-тесты. React находится в соседнем `D:/work/maxim-frontend` и в задачи реализации этого плана не входит.
- Общий checkout используется несколькими чатами планирования; не переключать ветку и не изменять чужие планы. При реализации передавать путь конкретного плана явно в `$aif-implement`.

## Последовательность выпуска и ограничения

1. Основной план можно выполнять независимо от двух крупных планов. Общие generated API/документы объединять последовательно.
2. Backend B1/B2/B4/B5 выпустить до использования новых возможностей фронтом. Старый фронт совместим: прежние маршруты остаются, новые поля optional.
3. По комиссии и плашке выполнить собственные правила совместимости/rollout в отдельных планах. При откате не переписывать историю денег и immutable media snapshot.
4. После backend-выпуска актуализировать промпт фронтенда. Для UI support пока требуются реальные ссылки Telegram/MAX; точный новый дизайн плашки остаётся предложением в отдельном плане. Эти сведения не блокируют остальные backend-задачи.
5. Этот план не включает деплой, изменения production/dev-секретов и живые вызовы финансовых API. Для планирования серверный доступ не требуется.
