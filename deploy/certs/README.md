# Корневые сертификаты для внешних систем

Сервер MAX Bot API использует сертификат Минцифры (05 §2.1). Корневой сертификат
кладётся сюда и попадает в образ бэкенда в `/etc/maxim/certs/`:

1. Скачать «Russian Trusted Root CA» в формате PEM с официального ресурса Минцифры
   (Госуслуги, раздел о сертификатах НУЦ) и сохранить как `russian_trusted_root_ca.pem`.
2. Сверить отпечаток SHA-256 с опубликованным на официальном ресурсе:
   `openssl x509 -in russian_trusted_root_ca.pem -noout -fingerprint -sha256`.
   Записать отпечаток и дату проверки в этот файл.
3. В окружении `worker` задать `MAX_CA_CERT_FILE=/etc/maxim/certs/russian_trusted_root_ca.pem`.

Без сертификата `worker` в продакшене не стартует: проверка бота (`GET /me`) не
пройдёт TLS. В разработке и тестах MAX поддельный, сертификат не нужен.

## Проверка для Т-Банка — 2026-11-11

В репозитории сохранён **публичный** корневой сертификат `russian_trusted_root_ca.crt` (PEM), полученный по HTTPS с ресурса Госуслуг:
https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt

SHA-256 DER-сертификата (openssl x509 -fingerprint -sha256):
`D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`.
Срок действия: 2022-03-01 21:04:15 UTC — 2032-02-27 21:04:15 UTC. Отпечаток вычислен по скачанному сертификату; это не отдельное письменное подтверждение банка.

Переход API на эту цепочку описан в [документации Т-Банка](https://developer.tbank.ru/docs/tls-settings). С данным корнем фактически прошли TLS-проверка hostname/цепочки и HTTP 200 на `business.tbank.ru/openapi/sandbox/api/v1/statement`. Промежуточный сертификат сервер передал сам; дополнительно доверять ему как корню не потребовалось. Без корня Linux curl возвращал ошибку 60.

В Docker файл доступен как `/etc/maxim/certs/russian_trusted_root_ca.crt`; используется только при явном `TBANK_CA_CERT_FILE`. В локальном `.env` путь — `deploy/certs/russian_trusted_root_ca.crt`. Системное хранилище Windows/Linux не менялось, TLS-проверка не отключалась. Для ротации загрузите актуальный файл с официального ресурса по проверенному HTTPS, сверьте fingerprint и срок, повторите sandbox-чтение и обновите эту запись. CA — публичный trust anchor; клиентские ключи и токены сюда не помещать.
